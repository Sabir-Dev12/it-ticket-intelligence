# Publier dans la Knowledge Base

Un Admin ouvre Knowledge base puis **Add document** (`/knowledge/new`). Il saisit titre, source, catégorie, type et contenu, ou importe un fichier TXT/Markdown UTF-8. Le fichier est lu dans le navigateur puis envoyé comme contenu texte via le `POST /api/knowledge` existant ; aucun endpoint d'upload ou de conversion PDF/Word n'est inventé. L'import remplace le contenu et propose le nom du fichier comme titre/source. Limites : 400 KB à l'import, 100 000 caractères de contenu, titre de 160 caractères et source de 512 caractères. Les contenus sont affichés comme texte, sans exécution HTML.

Après sauvegarde réelle, le détail du document s'ouvre. Back to knowledge retourne à la bibliothèque ; les cartes sont chargées depuis l'API et proposent titre, catégorie, type, format et date. La recherche et la pagination existantes restent disponibles. Agent et Support consultent les documents autorisés et leur lien Ask AI ; la publication reste réservée à Admin, avec garde de route et refus serveur.

L'option d'indexation appelle ensuite le `POST /api/rag/documents/{id}/index` existant. Une acceptation 202 signifie que le traitement est demandé en arrière-plan, pas qu'il est déjà terminé. Le Worker crée les embeddings avec Ollama. Un échec de cette demande ne transforme pas la sauvegarde réussie en échec et ne recrée pas le document. Le formulaire conserve le contrôle des soumissions concurrentes, les erreurs de validation et l'avertissement de navigation avec modifications non sauvegardées. Après une issue réseau inconnue, il demande de vérifier la bibliothèque avant de retenter.

Validation : build frontend et 36 tests unitaires réussis ; deux scénarios navigateur réels réussis séparément. Le scénario Admin vérifie validation, import, publication, consultation, présence dans la liste, acceptation du job, achèvement Succeeded et résultat de recherche RAG pour le document publié. Le scénario Support vérifie l'absence du bouton et le refus HTTP 403 d'une publication. Axe est vérifié dans les deux thèmes et l'absence de débordement à 280/320/414/1280 pixels. Captures : `artifacts/frontend/knowledge-create-{light,dark}.png`. Un guide de démonstration SQL Server est conservé dans la bibliothèque locale.

Le gate global du kit reste 0/52 faute de scripts et harness de référence configurés dans ce dépôt (`artifacts/frontend/knowledge-design-gate.txt`). Les contrôles ciblés ci-dessus ne constituent pas une validation de toute la suite historique ni une certification de ce gate global. Aucun backend ou schéma SQL n'a été modifié pour ce parcours.
